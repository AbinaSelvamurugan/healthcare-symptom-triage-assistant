# Privacy, secrets, retention, and processing

Symptoms are sensitive health information. **Use only synthetic narratives.** The default application stores no symptom conversations on disk. Streamlit's session state temporarily holds the fictional chat history and process memory holds a minimal per-session sign map, rule IDs, statuses and transitions. Session IDs are random and never intended as persistent identifiers. Default session TTL: 30 minutes (checked on interaction). Reset deletes session-state text and core memory; expiry clears history. An actual hosted service would require formal retention verification and cleanup on crashes/restarts, backup deletion, processor contracts, privacy impact assessment, and secure authenticated sessions before handling sensitive information.

Event logging is metadata only (`event` and limited category identifiers); raw narratives, API keys, model prompts, HTTP bodies, IP addresses and personal identifiers are not intentionally logged. CareGuide does not instrument Streamlit or Anthropic service-level logs, which must be reviewed separately. No SQLite conversation persistence, analytics, data sharing or model training from user data is implemented.

External data transfer: Only `CAREGUIDE_MODE=claude_demo` sends a synthetic `GENERAL_INFO` input to Anthropic, along with the configured rule IDs/instruction and fixed system prompt. Mandatory escalation paths never call the model. Credentials use `ANTHROPIC_API_KEY` from the process environment, never source control; use a managed secrets facility in any hosted experiment. `.env` is gitignored, but do not upload it in debugging artifacts. There is no claim of HIPAA/GDPR compliance or an Anthropic provider retention guarantee.
