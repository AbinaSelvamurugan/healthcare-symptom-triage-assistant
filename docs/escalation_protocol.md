# Rule governance and escalation protocol

**Authoritative clinical protocol:** NONE. **Version:** NONE. **Jurisdiction:** UNSPECIFIED. **Clinical reviewer:** NONE. **Clinical review date:** NONE. **Approval:** No clinical review or approval has been performed. **Licensed source:** NONE. **Clinical applicability:** NONE. The existing `CAREGUIDE-SYNTHETIC-ONLY` version `0.1.0` is a software fixture, NOT clinical guidance. It cannot be promoted by editing YAML.

Each local `Rule` includes rule ID, version, target fictional population, phrase triggers, required fields, configured category, required instruction, source, review date, reviewer, approval state, and known limitations. The `Protocol` has separate ID/version, scope, jurisdiction and approval data. Pydantic enforces record shape and approval metadata, but metadata is NOT proof of clinical approval. `clinical_rules/validator.py` prohibits treating rules with `APPROVED` status as deployed in this demonstration. An independent audited approval path would need to be designed for clinical operation.

The demonstration priority ordering is `EMERGENCY > URGENT > GENERAL_INFO` for configured synthetic triggers. This is software precedence, **not a clinical triage scale**. The deterministic rule engine searches locally configured English token phrases and does limited explicit negation suppression. For any emergency match it immediately emits exactly the rule's instruction, optionally appending a configured contact; no model is called, no extra question is asked and all subsequent messages retain the emergency latch. Urgent flags similarly latch, but a later configured emergency can raise them. There is no downgrade process. Reset creates a new session; a patient-facing workflow would require a clinically authorized correction protocol.

**Unknown jurisdiction/contact:** The supplied config has `jurisdiction: unspecified` and `emergency_contact: null`; the system says *local emergency service* and invents no number. Only a governance-controlled configuration change could add jurisdiction-specific instructions. No unsupported timing window is supplied for the demonstration urgent rule. If a phrase does not match, an agreed limited synthetic question may be shown; after configured question budget, the service refers to a healthcare professional rather than declaring non-urgent.

Emergency-like example trigger phrases are fixture strings, not exhaustive symptom definitions. They must NEVER be used to clear a real user. No approved clinical scenarios, quantitative benchmarks, or medical accuracy claims exist.
